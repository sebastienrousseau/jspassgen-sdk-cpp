# Security Policy

## Supported versions

This library follows the
[jspassgen](https://github.com/sebastienrousseau/jspassgen) suite's
version. `0.0.22`, the first release, is the latest. While pre-`1.0`,
the latest released `0.0.x` receives security fixes; older `0.0.x`
versions do not.

| Version | Status | Receives security fixes? |
| :--- | :--- | :--- |
| `0.0.23` (planned, unreleased) | In development | Not released |
| `0.0.22` (latest) | Released 2026-11-18 | Yes |
| `main` | In development | Yes |

## Reporting a vulnerability

**Do not open a public issue for security reports.**

Use GitHub Private Vulnerability Reporting:
<https://github.com/sebastienrousseau/jspassgen-sdk-cpp/security/advisories/new>.
The maintainers are notified automatically.

Please include a description and its impact, a minimal reproducer
(preferably a failing test), the commit or version affected, and any
proposed fix. A vulnerability in the JavaScript core belongs in
[jspassgen's advisories](https://github.com/sebastienrousseau/jspassgen/security/advisories/new).

These are goals, not guarantees: the project is maintained in a personal
capacity, with no SLA. **Acknowledgement**: the goal is within 5 working
days. **Triage**: a severity assessment and remediation plan after
acknowledgement.

## Security posture

### Scope

The library reads random bytes from the operating system and turns them
into uniform integers. It makes no network call, has no telemetry,
writes no file and never logs. It does not generate passwords yet.

### Threat model

| Surface | How it's handled |
| :--- | :--- |
| **Weak randomness** | Only the OS CSPRNG is used: `getrandom(2)`, `arc4random_buf(3)` or `BCryptGenRandom` with the system-preferred RNG. There is no user-space generator and no fallback; an unknown platform fails to compile. |
| **Modulo bias** | `random_int(max)` rejects 64-bit words below `2^64 mod max`, so every value in `[0, max)` is equally likely. A test checks that a plain modulo shows the bias and `random_int` does not. |
| **Short reads** | `getrandom` partial reads and `EINTR` are retried until the buffer is full; any other failure throws `std::system_error`, never returns partly filled output. |
| **Secrets in errors** | Exception messages name the argument or the failing call only, never generated bytes. |
| **Exfiltration** | No network, telemetry or file I/O exists in the library. |
| **Dependency CVEs** | No run-time dependency. GoogleTest (tests only) is fetched from a release archive pinned by SHA-256. |

### Dependency audit

| Dependency | How it is obtained | How advisories are tracked |
| :--- | :--- | :--- |
| GoogleTest `1.18.0` (tests only) | Release archive, `URL_HASH SHA256` in `tests/CMakeLists.txt` | By hand: its GitHub security advisories are reviewed before a release or a pin bump. It is never linked into the library. |

Dependabot has no CMake `FetchContent` ecosystem, so it cannot propose
updates for the archive; it does track the workflow actions. A changed
upstream archive fails the CMake configure step on its SHA-256 instead
of building.
